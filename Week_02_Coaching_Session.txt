Nice, José — I see the pattern you’re using: importing your db connection and then wrapping queries in an async function. That structure makes sense because it keeps each query isolated and ensures you can await the database call. It also makes your model functions reusable across routes.

Exactly — async is the “main character” because it ensures your function pauses until the database finishes responding, so you don’t try to render or process incomplete data. That’s a solid foundation for reliable server-side logic.

But here’s the catch: while async/await guarantees the timing of data, it doesn’t guarantee the quality of the response. If the query fails, the connection drops, or the SQL has an error, your function could still break unless you handle those cases. That’s where try/catch blocks or error-handling middleware come in.

Exactly, José — you nailed the distinction. In EJS:

<%= %> is for outputting values directly into the HTML (like your title or category name). It escapes the content and ensures it’s displayed as text.

<% %> is for control flow or logic (like your if statement or forEach loop). It doesn’t output anything itself, but it lets you run JavaScript inside the template.

So yes, calling <% %> “dynamic content” is a fair way to describe it — it’s the logic that decides what gets displayed, while <%= %> is the actual display of values. Together, they make your template flexible and responsive to the data passed in.
